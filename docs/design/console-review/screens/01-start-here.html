1Apps

Connectors · Connections · Calls · Syncs · Events

Talk to GitHub, Slack, Notion and 70 other apps through one API and one auth flow. A call is one request to one app, recorded and replayable.

Use it when

  • —you need data from an app right now
  • —you want one auth flow for every provider
  • —you want records kept in sync or webhooks delivered

You get

  • —hosted OAuth and API-key storage
  • —typed tools per app, callable over HTTP or MCP
  • —background syncs with retries
  • —a log of every call with its trace

2Workflows

Workflows · Runs

Run multi-step work that must finish even if a step fails, a provider is slow, or a process restarts. Each step is recorded; the run resumes from where it stopped.

Use it when

  • —one task spans several calls or apps
  • —steps must retry or wait (hours, days) without losing state
  • —a human or another system has to signal the run to continue
  • —an effect may have happened and you need to prove it before retrying

You get

  • —durable runs with replayable history
  • —retries with a policy you set
  • —timers, signals, and child runs
  • —explicit reconciliation when an outcome is unknown

3

Rule of thumb. One call, one app, done in seconds: Apps. Several steps, or anything that must survive a failure: Workflows, whose steps call Apps. Example: “when a GitHub issue is labelled urgent, open a Linear ticket, post to Slack, and wait for an on-call ack” is a Workflow made of three Apps calls and one signal.
